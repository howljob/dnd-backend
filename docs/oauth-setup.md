# Вход через Google и VK ID — как включить

Код входа через Google и VK уже в проекте, но выключен: кнопки «Войти через …»
появятся на сайте автоматически, как только в `.env` бэкенда появятся ключи
приложений. Ключи выдают сами Google и VK — нужно один раз зарегистрировать
у них «приложение». Это бесплатно, займёт 10–15 минут на каждого провайдера.

Понадобится решить один вопрос заранее: **какой адрес у бэкенда**. Ниже
в инструкциях везде встречается «адрес бэкенда»:

- локально это `http://localhost:4000`;
- на проде — `https://ваш-домен` (тот же домен, что у сайта, потому что nginx
  проксирует `/api` на бэкенд). ⚠️ Google и VK принимают только `https` для
  боевых адресов — без HTTPS-домена вход работает только локально.

## Часть 1 — Google (console.cloud.google.com)

1. Зайдите на [console.cloud.google.com](https://console.cloud.google.com)
   под своим Google-аккаунтом.
2. Вверху слева выпадающий список проектов → **New Project** → название
   `DnD-Hub` → **Create** → дождитесь и выберите проект.
3. Меню (☰) → **APIs & Services → OAuth consent screen**:
   - выберите **External**, нажмите **Create**;
   - App name: `DnD-Hub`, User support email: ваша почта,
     Developer contact: ваша почта → **Save and Continue**;
   - на шагах Scopes и Test users ничего не добавляйте — **Save and Continue**
     до конца.
4. **APIs & Services → Credentials → Create Credentials →
   OAuth client ID**:
   - Application type: **Web application**;
   - Name: `DnD-Hub Web`;
   - **Authorized redirect URIs → Add URI** — введите ровно
     (замените адрес бэкенда на свой):

     ```
     <адрес-бэкенда>/api/auth/oauth/google/callback
     ```

     например `http://localhost:4000/api/auth/oauth/google/callback` для
     локальной проверки, и вторым URI — прод-вариант
     `https://ваш-домен/api/auth/oauth/google/callback`;
   - **Create**.
5. Google покажет **Client ID** (длинный, кончается на
   `.apps.googleusercontent.com`) и **Client secret** (начинается с `GOCSPX-`).
   Скопируйте оба.

## Часть 2 — VK ID (id.vk.com)

1. Зайдите на [id.vk.com/about/business/go](https://id.vk.com/about/business/go)
   (кабинет VK ID для разработчиков) и войдите через свой VK-аккаунт.
2. **Создать приложение**:
   - тип платформы: **Web**;
   - название: `DnD-Hub`;
   - **Доверенный redirect URL** — введите ровно (замените адрес бэкенда):

     ```
     <адрес-бэкенда>/api/auth/oauth/vk/callback
     ```

   - домен приложения: домен сайта (для локальной проверки — `localhost`).
3. После создания откройте настройки приложения. Понадобятся:
   - **ID приложения** (число) — это `VKID_CLIENT_ID`;
   - **Защищённый ключ** (сервисный/секретный ключ) — это `VKID_CLIENT_SECRET`.
4. В настройках доступа приложения включите право на получение **почты (email)**
   пользователя — без него вход не сможет связать аккаунты.

## Часть 3 — вписать ключи в .env

Откройте `.env` бэкенда, раскомментируйте и заполните блок:

```
GOOGLE_CLIENT_ID=…из части 1, шаг 5…
GOOGLE_CLIENT_SECRET=…из части 1, шаг 5…
VKID_CLIENT_ID=…из части 2, шаг 3…
VKID_CLIENT_SECRET=…из части 2, шаг 3…
OAUTH_CALLBACK_BASE=http://localhost:4000   ← адрес бэкенда (на проде https://ваш-домен)
```

Можно заполнить только одного провайдера — второй просто не появится на сайте.
Перезапустите бэкенд.

## Как проверить

1. Откройте сайт → **Войти**. В модалке под формой должны появиться кнопки
   «Войти через Google» / «Войти через VK ID» (какие настроены).
2. Нажмите кнопку → вас уведёт на страницу Google/VK → подтвердите вход →
   вернёт на сайт уже залогиненным (имя в правом верхнем углу).
3. Если у вас уже был аккаунт с той же почтой — вход произойдёт в него;
   если не было — аккаунт создастся автоматически, почта сразу считается
   подтверждённой.

## Частые проблемы

| Симптом | Причина |
|---|---|
| Кнопок нет в модалке | Ключи не в `.env`, или бэкенд не перезапущен |
| Google: `redirect_uri_mismatch` | Redirect URI в консоли не совпадает буква в букву с `OAUTH_CALLBACK_BASE` + `/api/auth/oauth/google/callback` |
| VK: ошибка redirect | То же про доверенный redirect URL в кабинете VK ID |
| После провайдера — «Вход через внешний сервис не удался» | Смотрите лог бэкенда, строки `[oauth]` — там точная причина (чаще всего неверный секрет или не выдано право на email) |
| Google предупреждает «приложение не проверено» | Нормально, пока приложение в режиме тестирования; нажмите Advanced → Continue. Для публики позже пройдите верификацию в консоли Google |
