# Аудит утечки секретов по истории git бэкенда

Дата: 2026-09-14, трек T1. Проверена вся история всех веток репозитория
`dnd-backend` (`git log --all -p`, `git grep` по всем коммитам).

## Факты

1. **Файл `.env` в git не попадал ни разу.** Ни в одном коммите ни одной ветки
   его нет; `.env` и `.env.*.local` корректно стоят в `.gitignore` с первого коммита.
   Реальные секреты прода/локали через git не утекали.

2. **`.env.example` закоммичен с первого коммита** (`c2f4259`, 2026-05-04) и
   содержит значения-заглушки для переменных: `PORT`, `NODE_ENV`, `PGHOST`,
   `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `JWT_ACCESS_SECRET`,
   `JWT_ACCESS_EXPIRES_IN`, `SMTP_*`, `TELEGRAM_BOT_TOKEN`, `FRONTEND_URL`.
   Проблема: значение `JWT_ACCESS_SECRET` в примере — не абстрактная заглушка
   вида `changeme`, а **правдоподобная осмысленная строка**. Если прод-`.env`
   создавался копированием `.env.example` и секрет не заменили — действующий
   JWT-секрет фактически опубликован.

3. **`docker-compose.yml` закоммичен** с паролем Postgres `postgres` (пользователь
   `postgres`) и пробросом порта `55432:5432`. Проброс в docker по умолчанию
   вешается на все интерфейсы (0.0.0.0): если прод поднимает базу этим же
   compose-файлом и порт 55432 не закрыт файрволом, база доступна из интернета
   с тривиальным паролем.

4. **Репозиторий публичный.** `github.com/howljob/dnd-backend` отвечает без
   авторизации (HTTP 200 из API GitHub) — всё перечисленное выше видно любому.

5. В коде секретов нет: JWT-секрет и пароль БД читаются только из окружения
   (`src/config/env.js`), в исходниках захардкоженных значений не найдено
   (поиск по всем коммитам: `JWT`, `SECRET`, `PASSWORD`, `TOKEN`, `KEY`, `PEM`).

## Рекомендации

| # | Что сделать | Срочность |
|---|---|---|
| 1 | На проде проверить: совпадает ли `JWT_ACCESS_SECRET` в `.env` со значением из `.env.example`. **Если совпадает — ротация обязательна немедленно** (сгенерировать: `openssl rand -hex 64`, вписать в `.env`, `systemctl restart dnd-backend`). Все пользователи будут разлогинены — это нормально. Если не совпадает — ротация желательна, но не горит. | Высокая |
| 2 | На проде проверить пароль Postgres. Если это `postgres` из compose-файла — сменить (`ALTER USER postgres PASSWORD '...'` + обновить `.env` и окружение контейнера) **и** закрыть порт 55432 снаружи (ufw или убрать проброс порта, оставив доступ только бэкенду). | Высокая |
| 3 | Заменить в `.env.example` значение `JWT_ACCESS_SECRET` на явную заглушку (сделано в этом же коммите: теперь там `CHANGE_ME_...`). | Сделано |
| 4 | При настройке HTTPS (T1.3) не забыть: пока прод ходит по HTTP, пароли пользователей и JWT-токены в любом случае видны в трафике — ротация секрета не спасает от этого. | К T1.3 |

## Что проверить может только человек с доступом к прод-серверу

- Значения `JWT_ACCESS_SECRET` и `PGPASSWORD` в прод-`.env` (совпадают ли с опубликованными примерами).
- Открыт ли порт 55432 наружу (`ss -tlnp`, правила ufw/облачного файрвола).
- Не лежит ли `.env` в веб-доступной папке и не раздаёт ли его nginx.
